Leaving cloud storage buckets vulnerable to public access control lists exposes sensitive assets to unauthorized external actors over the internet.

Checkov check CKV_AWS_53 inspects the configuration of the aws_s3_bucket_public_access_block resource to ensure that public access control lists are explicitly blocked.

An attacker can exploit overly permissive object access control lists over the S3 API to read or write private cloud storage objects. Unrestricted access control lists allow anonymous or public principals to bypass intended authorization boundaries on sensitive data buckets. Enabling block public ACLs stops the S3 service from accepting requests that attempt to grant public permissions via object and bucket access control lists.

The fix is to set the block_public_acls argument to true on the aws_s3_bucket_public_access_block resource.
