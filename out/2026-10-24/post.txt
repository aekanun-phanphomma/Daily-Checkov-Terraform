Can you pass policy validation simply by omitting the effect argument on an IAM statement?

When inspecting an aws_iam_policy_document data block, the scanner looks at each statement block for two arguments: effect and actions. The rule flags a failure whenever the actions list contains an asterisk while effect is explicitly set to Allow or left unspecified.

A detail that catches teams off guard is that omitting effect does not let wildcard actions slip through. Because Terraform defaults the statement effect to Allow, the scanner explicitly treats a missing effect as Allow and flags the asterisk action. Conversely, a statement with effect set to Deny and an asterisk action will pass without issue.

Allowing a wildcard action gives any identity using the policy full permission to execute administrative and data-plane operations across every service in the AWS account. A compromised credential or workload can immediately disable audit trails, create new credentials, or delete infrastructure.

Resolve this by replacing the wildcard in the actions list with specific API actions like s3:GetObject.
