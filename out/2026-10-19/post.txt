Can individual blob containers still permit anonymous internet reads if your storage account defaults seem secure?

The static analysis rule inspects the allow_nested_items_to_be_public argument on each azurerm_storage_account resource. It expects the boolean value to be false. If this argument is set to true, or if you omit it entirely from the configuration, the resource fails verification.

A common surprise is that simply omitting allow_nested_items_to_be_public results in a failure. Even if no containers currently permit anonymous access, leaving out an explicit false declaration leaves the resource open to future container-level exposure.

When nested items are permitted to be public, anyone can pull sensitive objects over standard REST endpoints without authenticating, bypassing private networking and authorization boundaries.

To fix this violation, set allow_nested_items_to_be_public to false on the azurerm_storage_account resource.
