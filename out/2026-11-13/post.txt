Myth: Assigning roles/editor to developers at the project level is safe because project boundaries prevent access to external infrastructure.

Fact: Basic primitive roles grant wide read, write, and delete permissions across virtually every Google Cloud service inside that project. An attacker who gains control of credentials with roles/editor can modify network configurations, read Cloud Storage objects, spin up compute instances, and alter logging parameters without restricted controls.

Static analysis fails configurations when google_project_iam_member or google_project_iam_binding resources grant basic primitive roles at the project level.

The fix updates the role argument to a predefined or custom fine-grained role such as roles/compute.viewer instead of primitive roles.

Which IAM role assumption has your engineering team had to unlearn when securing cloud projects?
