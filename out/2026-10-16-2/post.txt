Leaving SSH exposed to the public internet creates an immediate vector for automated brute-force attacks and remote server compromise.

Checkov check CKV_AZURE_10 flags Azure Network Security Group rules that permit inbound SSH traffic on port 22 from the public internet.

When an inbound NSG rule allows TCP traffic on destination port 22 with a source prefix set to any wildcard or internet tag, any host on the public internet can initiate a handshake with your virtual machines. Attackers continuously scan cloud IP spaces for listening SSH daemons to conduct automated credential stuffing, brute-force password guessing, and exploit unpatched software vulnerabilities. Once an attacker gains a foothold through an exposed port, they achieve interactive command execution within your network perimeter.

To resolve this misconfiguration, update the azurerm_network_security_rule resource by configuring source_address_prefix to a specific trusted CIDR block or private subnet such as 10.0.0.0/24 instead of a wildcard.
