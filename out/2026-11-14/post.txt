Can an IAM role attach an AWS managed policy without triggering a policy violation?

The rule looks directly at the managed_policy_arns argument on aws_iam_role resources. If the list contains the string arn:aws:iam::aws:policy/AdministratorAccess, the resource fails. Any other managed policy ARN passes. When scanning standalone attachment resources such as aws_iam_role_policy_attachment, it checks the policy_arn argument for that exact same string.

What surprises many engineers is how specific this rule is. You can attach a custom policy granting full wildcard actions across all resources, or attach PowerUserAccess, and this rule will still pass. It strictly checks for the exact AWS-managed AdministratorAccess ARN string.

Granting AdministratorAccess provides complete control over every AWS API. If an application or service assuming this role is compromised, an attacker can disable audit logging, provision persistent credentials, and alter cloud infrastructure across the entire account.

To fix the issue, update the managed_policy_arns argument to reference a scoped policy such as arn:aws:iam::aws:policy/ReadOnlyAccess instead of the administrator policy.
