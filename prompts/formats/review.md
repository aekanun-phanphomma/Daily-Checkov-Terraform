Format: CODE REVIEW COMMENT (600-1300 characters).
- Line 1: a one-line setup: a pull request with this change is waiting for
  approval, and one line in it is the problem. Hypothetical, no names.
- Then the review comment a senior engineer would leave on that line, in
  first person, two or three short paragraphs: what the line allows, who
  can reach what through which API or protocol, and the exact change to
  request (argument and value).
- Then one line saying {{check_id}} would have flagged it automatically.
- Last line: a one-sentence takeaway for reviewers. Not a question.
